# Vlog Agent 产品与技术骨架

> 状态：初稿，待评审
> 目标用户：零基础普通人（含零售端小 B、想做账号的素人），只有一部手机，不填表、不懂术语
> 产品定位：交付的不是知识，是判断——不教用户拍，替用户判断，从举起手机一直跟到发出去
> 范围：单做 vlog 并做透；跨小红书、YouTube、抖音、B 站等平台，按平台重新出片，而非同一文件改尺寸

---

## 1. 产品骨架

### 1.1 核心单位

**一次「拍摄项目」Project**：不是账号、不是单条视频，是从「我想拍点什么」到「发出去并回收反馈」的完整一次。多平台出片是同一 Project 下的多个交付包，不是多个独立任务。所有状态挂在这上面。

### 1.2 六个阶段，允许回退

| Stage | 输入 | 输出 |
| --- | --- | --- |
| 0 立项 | 一句话或一张图 | 意图卡（主题、观众、情绪基调、主发平台、预计时长） |
| 1 规划 | 意图卡 + 用户画像 | 镜头清单 8~12 条 |
| 2 拍摄 | 逐条指令 | 素材卡、清单完成状态、补拍提醒 |
| 3 剪辑 | 素材卡集合 | 入选素材 + 剪辑决策表 + 粗剪 |
| 4 发行 | 主叙事 + 平台策略 | 每个平台一份交付包 |
| 5 回收 | 数据 + 本次变更变量 | 复盘卡 + 画像更新 |

状态机不是单向流水线：

- 拍到一半发现主题不对，退回 Stage 1 改清单；
- 剪辑时发现缺镜头，退回 Stage 2 补拍，已通过的素材保留；
- 支持中断恢复——普通人一次拍不完，明天回来接着第 6 条。

### 1.3 输出物（Artifact）

每个都结构化、版本化保存；每次重生成留版本，才能归因「改了哪个变量」。

- **意图卡**：主题、目标观众、情绪、平台优先级、时长
- **镜头清单**：id / 叙事角色（钩子、环境、过程、特写、情绪、收尾）/ 拍什么 / 景别 / 时长 / 是否需出镜 / 状态（待拍、已拍、通过、需重拍）/ 关联素材 id
- **素材卡**：文件与时间码 / 画面内容 / 质量判定 / 景别 / 人声段 / 环境音可用段 / 对应清单项 / 判定原因
- **剪辑决策表**：镜头顺序 / 每段 in-out 与时长 / 转场 / 音轨分层（人声、环境、音乐）/ 留白点 / 字幕
- **交付包**（每平台一份）：成片规格（比例、分辨率、时长、帧率）、标题候选、封面、正文描述话题、发布时间、钩子位置
- **复盘卡**：本次只改了哪个变量、数据表现、结论、下次沿用策略

### 1.4 确认门（Gate）

用户只做极简确认，不逐步审。

| 类别 | 内容 |
| --- | --- |
| 自动通过 | 素材判定、清单推进、粗排、文案生成 |
| 必须点一下 | 立项时选主题方向、成片发出前、删除涉及私人场景的素材、是否全平台发 |
| 绝不自动 | 发布动作本身，先给预览 |

每次 Gate 的用户选择都记入事件日志，这是「越用越懂」最便宜且最真实的偏好标签来源。

### 1.5 长期状态（跨 Project 的用户画像）

出镜与否、节奏偏好、是否会剪（决定输出成片还是决策表）、设备、哪类叙事结构与钩子在自己的题材上有效、主发平台权重。只存偏好与策略结论，不存原始素材。

### 1.6 「高级」评分卡

两个用途：agent 出片前自检；告诉用户「这次比上次好在哪」（一次只报一个维度）。

| 维度 | 算法 |
| --- | --- |
| 钩子 | 前 3 秒（抖音）/ 前 30 秒（YouTube）是否有承诺或悬念；规划阶段标记、剪辑后校验 |
| 景别多样性 | 识别出的景别种类 / 清单要求的种类 |
| 单镜头时长分布 | 是否同时存在快切与长镜头，形成节奏起伏 |
| 细节特写 | 特写类素材被选入时间线的条数 |
| 声音层次 | 人声、环境音、音乐是否齐备；有无纯环境音留白 |
| 叙事闭环 | 开场提出的钩子在结尾是否回收 |
| 清单完成率 | 通过镜头数 / 计划镜头数（过程指标，单独计算） |

## 2. 技术骨架

### 2.1 分层

1. **交互层**：语音播报指令、清单勾选、拍照或上传素材、成片预览、极简确认。第一版不做实时相机流。
2. **编排层**：Project 状态机、Stage 推进、Gate 判定、回退与恢复。这是 agent 本体。
3. **能力层**：一组有明确输入输出契约的工具，见 2.2。
4. **模型路由**：按任务分派，见 2.3。
5. **存储层**：见 2.4。
6. **渲染层**：ffmpeg 做粗剪与音轨混合；成片规格由配置表驱动。

### 2.2 能力层工具清单

| 工具 | 输入 → 输出 |
| --- | --- |
| `parse_intent` | 一句话或一张图 → 意图卡 |
| `plan_shotlist` | 意图卡 + 用户画像 + 平台策略 → 镜头清单 |
| `next_instruction` | 当前清单状态 → 下一条拍摄指令（语音文案） |
| `judge_clip` | 一段素材 → 素材卡（多模态，见 2.5） |
| `check_shotlist` | 已拍素材 vs 清单 → 缺哪些 / 哪些要重拍 |
| `select_and_order` | 素材卡集合 + 叙事结构 → 入选素材 + 顺序 |
| `build_timeline` | 入选素材 + 平台规格 → 剪辑决策表 |
| `render_roughcut` | 决策表 → 粗剪文件（ffmpeg）或剪映草稿工程 |
| `adapt_platform` | 主叙事 + 平台策略 → 各平台交付包 |
| `review` | 数据 + 本次变更变量 → 复盘卡 + 画像更新 |

### 2.3 模型路由

不要一个模型全包。

| 任务 | 模型档位 | 约束 |
| --- | --- | --- |
| 意图分类、状态判断、现场指令 | lite | 现场链路硬约束是低延迟，慢了就没有在场感 |
| 单条素材的画面理解 | 多模态模型 | 抽关键帧后调用 |
| 叙事规划、时间线决策、平台改写 | 主模型 / reasoning | 允许较慢，放在规划与剪辑阶段 |

### 2.4 存储

- **Project 状态**：结构化、可序列化，支持中断恢复。
- **素材**：原始文件不动；派生抽帧、缩略图、音频波形、人声转写。
- **Artifact**：版本化，每次重生成留版本。
- **事件日志**：每次状态变更与 Gate 选择（谁触发、什么动作、用户是否确认），可回放。
- **用户画像**：跨 Project 持久化，只存偏好与策略结论。

### 2.5 素材判定 `judge_clip`

不要指望一次多模态调用给出全部结论，拆成三路再汇合。

| 路径 | 方法 | 说明 |
| --- | --- | --- |
| 技术质量 | 确定性算法：清晰度（模糊检测）、抖动（帧间位移）、时长、曝光直方图、近重复（感知哈希） | 不用模型；便宜、可解释、能单测；这一层是硬门槛 |
| 内容理解 | 抽关键帧 → 多模态模型 | 画面里是什么、景别、有没有人、能否对应清单哪一条、属于哪个叙事角色 |
| 音频 | 分离人声 / 环境 / 静音段，转写人声 | 标出可用环境音区间，留给「留白」使用 |

汇合规则：

- 技术质量不合格直接判「需重拍」，并给出具体原因字段（例如「糊了，重拍一条」）；内容理解负责归档到清单项与叙事角色。
- **判定结果必须带可解释原因**：现场要立刻告诉用户为什么，这个字段也是后续评测与提示优化的样本。
- 误判代价不对称：把好片判成糊、让人白重拍，比漏过一条差片更伤体验。低置信度时只给「可选重拍」，不强制。

### 2.6 平台适配策略表

用配置表驱动，不要写死在 prompt 里。每个平台一条配置：

比例、时长区间、钩子位置、节奏密度、字幕要求、标题风格、封面规则、发布时间、合规词表（导流、音乐版权）。

`adapt_platform` 读表加主叙事，重新排时间线，不是裁画面。加平台 = 加一条配置，不动主流程。

### 2.7 评测

分两套，不要混。

- **模块级（离线可跑）**：`judge_clip` 技术判定的准确率与误判率（尤其误判为糊）、`plan_shotlist` 清单完整性、`build_timeline` 的时长与结构约束满足率。
- **端到端（对照实验）**：同一件小事，对照组自己拍、实验组走流程；用 1.6 评分卡比钩子、景别多样性、细节特写、声音层次、叙事闭环；同时记过程指标——完成率、重拍次数、耗时、放弃点在哪一步。

## 3. 第一版裁剪

**做**：一句话或一张图 → 镜头清单 → 逐条指令加上传单条素材当场判定 → 素材收齐出剪辑决策表与一条 ffmpeg 粗剪 → 一个平台的标题封面包 → 复盘卡。

**不做**：实时视频流分析（先用「拍完上传单条」替代，延迟可控、实现简单）、自动发布、多平台并行适配、剪映工程导出、平台数据接口（先让用户手填两个数）。

第一版只验一个假设：**把现场判断外包给 agent，普通人能不能产出结构完整的 vlog**。其余是后续扩展，不是这一版要验的东西。

## 4. 下一步

先做 `judge_clip` 的技术判定与 Project 状态机：两者不依赖模型效果、能离线单测，又是整条链路的地基；跑通后其余模块都能挂上去试。

## 附：设计前提与边界

- 「不是课程」的实质：课程给通用知识、要人自己迁移；本产品针对这一次、这一堆素材、这个场景给具体决策，并全程跟随。
- 普通人拍不好 vlog 的主因不是设备或剪辑熟练度，而是拍之前没定下要讲什么故事、现场不知道该留该舍。
- 现场提示要克制，补拍建议判断错了比不提示更烦人。
- 素材判定准确率直接决定体验；自动成片有审美天花板，第一版定位为「粗剪 + 决策表」，用户保留最终剪辑权。
- 素材是私人生活，原始文件默认本地处理；平台音乐版权另作合规处理。
